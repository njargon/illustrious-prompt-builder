# Illustrious Prompt Builder - Prototype v9

## 目的

v8では実採用数が約8,674タグでした。
15,000前後を目標にするには、単なる上限増加ではなく
**未分類タグを落とさない構造**が必要だと判断し、v9では次を行いました。

- 小カテゴリをさらに増やす
- 各大カテゴリに「その他」系の受け皿を追加する
- Adult を維持する
- 最後まで分類できないタグ用に Misc カテゴリを追加する

## 大きな変更

### 1. 小カテゴリの増加
Character / Clothing / Pose / Composition / Environment / Objects / Effects / Adult
のすべてで小カテゴリを追加しました。

### 2. 受け皿カテゴリの追加
各大カテゴリに例えば次のような受け皿を追加しています。

- Character > 人物その他
- Clothing > 衣服その他
- Pose / Action > ポーズその他
- Composition > 構図その他
- Environment > 背景その他
- Objects > 物体その他
- Effects / Style > 効果その他
- Adult > 成人向けその他

### 3. Misc カテゴリの追加
分類ルールで最後まで取りこぼしたタグを受けるために、次を追加しました。

- Misc > テーマ・イベント
- Misc > 抽象・概念
- Misc > 未分類その他

### 4. Adult の扱い
成人向けタグは引き続き採用します。
ただし、未成年を明示・強く示唆する性的タグは除外します。

### 5. ランダム
- Adultカテゴリ内のカテゴリランダムは可能
- 上部の全体ランダムからは Adult / Misc を除外

## 容量

カテゴリ上の理論容量は **34,760タグ** です。
実際の採用数はブラウザでCSVを読んだ結果に依存します。

## ローカル確認

```bash
cd ~/Downloads/prompt-builder-prototype-v9
python3 -m http.server 8000
```

ブラウザで:

```text
http://localhost:8000
```

画面上部の `Danbooru由来 xxxx tags` が実採用数です。

## v11の変更

### loving_aura / aura系の分類
`Effects / Style > オーラ・感情エフェクト` を追加しました。

`loving_aura` のように、Danbooruデータには存在するが従来の
fallbackカテゴリ上限で落ちやすかったaura系タグを明示的に分類します。

### 右ペインの順序
右側を次の順番に変更しました。

1. カテゴリ別の選択済みタグ
2. コピー / Prompt読込 / ← / →
3. コピー用の平文Prompt

これにより、平文Promptのテキストエリアが不必要に縦へ伸びにくくなります。

### Prompt読込
`Prompt読込` ボタンを追加しました。

対応:
- `long_hair` / `long hair`
- `(blue eyes:1.2)`
- `[tag]`
- `{tag}`
- `1.2::tag::`
- Danbooru CSVのalias

操作:
- 「現在を置換して読込」
- 「現在に追加」

辞書にないタグは追加せず、未認識一覧として表示します。


## v12の変更

### 小カテゴリ上限を完全撤廃
v11まで存在した各小カテゴリの `220件` / `280件` / `1000件` などの
採用上限を削除しました。

`post_count >= 200` かつ分類対象になったタグは、
小カテゴリの件数に関係なくすべて登録されます。

### 部分文字列一致バグを修正
従来の分類器は:

```js
tag.includes(x)
```

を使っていたため、例えば `v` が `loving aura` の内部に含まれるだけで
「手のジェスチャー」に誤分類される問題がありました。

v12では単語・句の境界を考慮した照合に変更しました。

例:
- `v` は `v` や独立した `v` にだけ一致
- `man` は `woman` に一致しない
- `cat` は `cat ears` には一致

### loving aura
`loving aura` / `loving_aura` は
`Effects / Style > オーラ・感情エフェクト`
として明示的に分類します。

### 表示件数
データ採用上限は撤廃しています。
大量タグによるUI負荷が必要になった場合は、
採用件数ではなく「画面に一度に描画する件数」を別途制御します。


## v13の変更

### full-face blush の誤分類を修正
`full-face blush` が `Composition > 画角・写る範囲` に入っていた原因は
ハイフンそのものではなく、画角タグ一覧にある単独タグ `face` が
複合タグ内でも一致していたことでした。

v13ではCompositionの既知タグ一覧を完全一致判定に変更しました。

例:
- `face` → Composition > 画角・写る範囲
- `full-face blush` → Character > 表情
- `full face blush` → Character > 表情

一般的なfallback分類は残しているため、Composition全体が完全一致のみになるわけではありません。


## v14の変更

### 強調構文
右側の操作エリアに `強調設定` を追加しました。

操作:
1. `強調設定` を押す
2. 現在選択中のタグから強調対象を複数選択
3. 強度を1つ指定
4. `適用`

出力例:

```text
1girl, (long hair:1.25), (blue eyes:1.25), white shirt
```

強度は選択したタグすべてに一律適用されます。

### 強調状態の表示
右側のカテゴリ別タグ一覧でも、強調中のタグには強度バッジを表示します。

### Undo / Redo
強調設定もUndo / Redoの履歴に含めました。

### 削除との連動
タグをPromptから削除した場合、そのタグの強調設定も自動的に解除されます。


## v15の変更

### 1. Prompt読込時の強調復元
以下のようなPromptを読み込むと、

```text
1girl, (long hair:1.2), (blue eyes:1.2), white shirt
```

タグだけでなく、

- `long hair`
- `blue eyes`
- 強度 `1.2`

まで復元します。

現在の強調機能は「選択タグすべてに同じ強度」を使う仕様なので、
読込Prompt内に複数の異なる強調値がある場合は、
タグのみ読み込み、強調は自動復元しません。
その場合は読込画面に理由を表示します。

### 2. localStorageによる自動保存
以下をブラウザ内に自動保存します。

- 選択中のタグ
- 強調対象タグ
- 強調値

GitHub Pagesのサーバー側ではなく、
その端末・ブラウザの `localStorage` に保存されます。

同じURLを再読み込み・再訪問したときに自動復元します。
SafariのWebサイトデータを削除すると保存内容も消えます。

### 3. 大量タグの段階表示
タグデータ自体は全件保持しますが、
小カテゴリおよび全体検索結果は最初の300件だけ描画します。

続きがある場合は、

```text
さらに300件表示
```

ボタンを表示します。

検索自体は表示済み300件だけではなく、全タグを対象に行います。
